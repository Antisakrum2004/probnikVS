## 1. Что это за проект

Демо интеграции **1С:МИС (8.3.27, Казахстан)** с платформой **EmAI** и **Jitsi Meet** для проведения видеоконсультаций врач↔пациент.

**Цель:** Показать клиенту рабочий прототип — врач создаёт консультацию в 1С-стиле интерфейсе, пациент получает push в APK, оба подключаются к видео.

**Архитектура по ТЗ (Notion):**
```
1С МИС → PHP Middleware → EmAI Gateway → Jitsi Meet (msi-2.dialog.ip:58443)
```

**Реальная демо-архитектура:**
```
Next.js (Vercel) → API routes → EmAI → Jitsi Meet
                   (заменяет PHP middleware для демо)
```

**Ссылки:**
- Демо: https://probnik-vs-app.vercel.app/
- GitHub: https://github.com/Antisakrum2004/probnikVS
- ТЗ: https://www.notion.so/36c5ca3a0f2680bb97e2cfbbeac03df4
- APK: https://probnik-vs-app.vercel.app/Videokons_MIS.apk

## 3. Текущий стопор — ЧТО НЕ ТАК

### Проблема: Jitsi iframe не загружается

Страница `/video/[roomId]` загружается (200 OK), отображает спиннер "Получение токена авторизации...", но видео **не начинается**.

### Возможные причины (по приоритету):

#### 1. `msi-2.dialog.ip:58443` — частный сервер, недоступен извне
**САМОЯ ВЕРОЯТНАЯ ПРИЧИНА.**

Сервер `msi-2.dialog.ip:58443` — это локальный Jitsi на инфраструктуре заказчика. Он:
- Доступен только из внутренней сети (VPN/локальная сеть)
- Может использовать самоподписанный SSL-сертификат
- Не доступен с серверов Vercel (AWS US East)

**Проверить:** `curl -v https://msi-2.dialog.ip:58443/` — если timeout/connection refused — сервер недоступен извне.

**Решение:**
- Вариант A: Дать доступ к серверу (проброс порта, VPN)
- Вариант B: Для демо — временно использовать публичный `meet.jit.si` (без JWT, работает из коробки)

#### 2. JWT-токен не принимается сервером
Даже если сервер доступен, он может не принимать наш JWT по причинам:
- `test_jitsi_app_id` / `test_jitsi_app_secret` — тестовые, не сконфигурированы на сервере
- В формате JWT может быть ошибка (поле `moderator`, `context.user`, и т.д.)
- Сервер Jitsi может быть сконфигурирован с другим `app_id`

**Проверить:** Посмотреть в DevTools → Network → запрос к Jitsi серверу → ответ с ошибкой авторизации.

#### 3. HTTP/HTTPS mixed content
Если сервер Jitsi использует самоподписанный сертификат, браузер может заблокировать загрузку iframe.

#### 4. Версия Jitsi на сервере устарела
Если на `msi-2.dialog.ip:58443` старая версия Jitsi, она может не поддерживать параметры iframe, которые мы передаём.

| Протестировать что iframe Jitsi реально открывается | Разработчик | 5 мин |

### Приоритет 2: Push-уведомления в APK

Текущее состояние: APK показывает "Ожидание консультации" и не получает push. Push-уведомления через EmAI не работают потому что:
- Нет FCM (Firebase Cloud Messaging) проекта
- Нет Google Services JSON в APK
- EmAI не может отправить push без device token

| Действие | Кто делает |
|----------|-----------|
| Создать FCM проект в Firebase Console | Разработчик |
| Добавить `google-services.json` в APK | Разработчик |
| Зарегистрировать device token в EmAI | Разработчик |
| Настроить EmAI для отправки push | EmAI команда |

### Приоритет 3: Production-развёртка

| Действие | Кто делает |
|----------|-----------|
| Развернуть Jitsi Docker на сервере | Админ |
