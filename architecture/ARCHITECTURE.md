## Потоки данных

### Поток 1: Создание видеоконсультации
```
1С → POST middleware/?action=create (JSON) 
  → Middleware → POST EmAI /conference/create (JSON + API Key)
  → EmAI возвращает {emaiSessionID, videoRoomURL}
  → Middleware генерирует JWT для врача (role=owner) и пациента (role=member)
  → Middleware возвращает в 1С:
    {
      doctorLink:  "https://msi-2.dialog.ip:58443/18?jwt=...",
      patientLink: "https://msi-2.dialog.ip:58443/18?jwt=...",
      emaiSessionID: 18,
      message: "Запрос выполнен успешно"
    }
  → 1С сохраняет doctorLink в РС
  → EmAI отправляет patientLink пациенту через push
```

### Поток 2: Подключение врача
```
1С → "Начать видеоконсультацию" 
  → Читает doctorLink из РС
  → ЗапуститьПриложение(doctorLink) → открывает системный браузер
  → Jitsi проверяет JWT → врач получает права owner
```

### Поток 3: Завершение
```
1С → POST middleware/?action=complete (JSON)
  → Middleware → POST EmAI /conference/event {action: "COMPLETE"}
  → EmAI подтверждает
  → 1С ставит "Прием проведен" = Истина
```

### Поток 4: Отмена
```
1С → POST middleware/?action=cancel (JSON)
  → Middleware → POST EmAI /conference/event {action: "CANCEL"}
  → EmAI подтверждает
  → 1С ставит "Прием запланирован" = Ложь
```

## Преимущества middleware-слоя

1. **Безопасность:** API-ключ EmAI и JWT-секрет хранятся только на сервере, не в коде 1С
2. **Единая точка:** При смене URL EmAI или Jitsi — правится 1 файл (.env)
3. **Логирование:** Все запросы логируются на стороне middleware
4. **Валидация:** Проверка обязательных полей до отправки в EmAI
5. **Обратная совместимость:** Старые вызовы генерации JWT (?room&user&role) продолжают работать
6. **Формирование ссылок:** 1С получает готовые ссылки, не нужно генерировать JWT внутри 1С
